Contexto

O repositório faz trabalho de padrão-ouro e não se apresenta como tal. A auditoria de portfólio encontrou um projeto sem LICENSE, sem integração contínua, sem uma única imagem, e com números que se contradizem entre páginas. A Camada 0 não constrói recurso novo: ela faz o repositório dizer a verdade sobre si mesmo — que é a pré-condição de tudo o que vem depois, porque a Camada 1 torna este repositório público e histórico público não se apaga.

O achado mais caro é o da fatia-03, e ele foi medido nesta rodada: o notebook de controle de qualidade publicado em analysis/02_labeling_campaign_qc.html afirma literalmente agreement score: 0 of 155 e agreement = None (not measured): 155, enquanto o labeling/manifest.json registra 82 lotes concluídos e 73 pendentes e o README anuncia agreement de 0,913. Um avaliador que abra as duas páginas encontra o projeto se desmentindo. A prosa de analysis/README.md carrega o mesmo estado velho ("All 155 batches are pending"), e foi por isso que o dono emendou o R3: a fatia subiu de S para M e o arquivo entrou no escopo.

O segundo achado é sobre processo, não sobre número. O README cita 1.287 testes num ponto e 1.273 em outro; o CLAUDE.md diz 1.466; a medição desta rodada deu 1.467. Quatro números para o mesmo fato significam que corrigir o número não resolve — por isso a decisão D10 do PRD exige uma fonte única com verificação automática, e não uma edição pontual.

Regras invariantes

Regras do CLAUDE.md e da rodada que valem em todos os sprints:

  • uv não está no PATH desta máquina. Todo comando usa o caminho completo: & "$env:USERPROFILE\.local\bin\uv.exe" ...
  • PowerShell corrompe encoding em redirecionamento. > e Out-File gravam UTF-16/BOM e quebram acentuação. Nenhum arquivo deste plano (LICENSE, README, ci.yml) é escrito por redirecionamento — só por ferramenta de edição ou por Python.
  • Um sprint por vez, com checkpoint humano entre eles. Nada de dois sprints abertos.
  • Não editar prd-padrao-ouro.html nem adr-bancada-multi-tenant.html (instrução do dono, 2026-08-13): são o insumo canônico, já commitados em d85fefa.
  • Nunca commitar data/, nem ler parquet com ferramenta de texto.
  • Push para o remoto é ação externa e só acontece com aprovação explícita no checkpoint.
  • A Camada 1 não começa aqui. git filter-repo é destrutivo e depende da C0 verde mais aprovação em separado.

Por que esta ordem

É a ordem do PRD, e ela também é a ordem do risco. O S02 é o único sprint que depende de uma máquina que não é esta: a suíte nunca rodou em Linux, e se algo quebrar por caminho ou encoding é melhor descobrir cedo, com dois sprints ainda por fazer, do que na véspera de tornar o repositório público. O S04 vem por último de propósito — ele consolida o README depois de o badge (S02) existir e de os notebooks (S03) estarem frescos, para não editar o mesmo arquivo três vezes com informação que ainda vai mudar.

O que é isto, em 30 segundos

Este é o roteiro de quatro tarefas para arrumar a fachada de um projeto de software — a parte que alguém de fora vê antes de olhar o conteúdo. Nenhuma das quatro cria funcionalidade nova. Elas dão ao projeto uma licença de uso, um verificador automático que roda a cada mudança, relatórios de qualidade atualizados e uma página inicial que não se contradiz. Importa para quem vai avaliar este trabalho numa candidatura: hoje a página inicial afirma uma coisa e um relatório interno afirma outra sobre o mesmo assunto.

This is the roadmap for four tasks that fix a software project's storefront — the part an outsider sees before looking at the substance. None of the four builds a new feature. They give the project a usage licence, an automatic checker that runs on every change, up-to-date quality reports, and a front page that does not contradict itself. It matters to whoever will assess this work in a job application: today the front page says one thing and an internal report says another about the very same subject.

Por que isto existe

Uma revisão externa do projeto encontrou quatro buracos. Primeiro: não havia arquivo de licença, e sem ele ninguém sabe legalmente o que pode fazer com o código. Segundo: não havia verificação automática — a garantia de que os 1.467 testes do projeto passam dependia de alguém lembrar de rodá-los à mão. Terceiro, e o pior: um relatório de qualidade publicado no projeto diz que a campanha de classificação de dados mediu zero de 155 lotes, quando na verdade 82 já foram feitos, com uma taxa de concordância de 0,913 — numa escala em que 1,0 seria concordância total e 0,80 é o mínimo exigido. O relatório foi gerado antes do trabalho e nunca refeito. Quarto: a página inicial cita a quantidade de testes em dois lugares com dois números diferentes, e nenhum dos dois é o número certo.

An external review of the project found four gaps. First: there was no licence file, and without one nobody legally knows what they may do with the code. Second: there was no automatic checking — the guarantee that the project's 1,467 tests pass depended on someone remembering to run them by hand. Third, and the worst: a quality report published in the project states that the data-labelling campaign measured zero out of 155 batches, when in fact 82 have been done, with an agreement rate of 0.913 — on a scale where 1.0 would be total agreement and 0.80 is the required minimum. The report was generated before the work and never regenerated. Fourth: the front page cites the number of tests in two places with two different figures, and neither of them is the right one.

O que muda daqui pra frente

Fica mais fácil confiar no projeto sem executá-lo: a licença responde à pergunta legal, as imagens mostram o produto funcionando e os relatórios passam a bater com a realidade. Fica mais caro ser desleixado, de propósito: a verificação automática roda a cada alteração enviada, e o número de testes da página inicial passa a ser conferido por um teste que falha se alguém deixar os dois divergirem — que é a diferença entre corrigir um número e corrigir o hábito que o estragou três vezes. O que não se desfaz é nada, ainda: esta etapa inteira é reversível. A etapa seguinte, que reescreve o histórico do projeto para remover um arquivo com dados pessoais e depois o torna público, é que não tem volta — e por isso ela exige uma aprovação separada e uma cópia de segurança antes.

It gets easier to trust the project without running it: the licence answers the legal question, the images show the product working, and the reports start matching reality. It gets more expensive to be sloppy, deliberately: the automatic check runs on every change submitted, and the test count on the front page starts being verified by a test that fails if anyone lets the two drift apart — which is the difference between fixing a number and fixing the habit that broke it three times. Nothing is undoable yet: this entire stage is reversible. The next stage, which rewrites the project's history to remove a file containing personal data and then makes it public, is the one with no way back — which is why it requires separate approval and a backup copy beforehand.

O que isto NÃO diz

Este plano não torna o projeto público — isso é a etapa seguinte, e ela depende de aprovação à parte. Ele não promete que o selo de "verificação passando" vai aparecer para qualquer visitante: enquanto o projeto for privado, esse selo só é visível para o dono, e o plano diz isso em vez de fingir que o critério foi cumprido. Ele não mede a qualidade dos dados com anotadores humanos novos, nem melhora o desempenho do classificador automático — são etapas posteriores, com custo próprio. E ele não garante que a verificação automática vai funcionar de primeira: o conjunto de testes nunca foi executado no tipo de máquina que a verificação usa, e o plano já carrega a alternativa caso quebre.

This plan does not make the project public — that is the next stage, and it depends on separate approval. It does not promise that the "checks passing" badge will show up for any visitor: while the project is private, that badge is only visible to the owner, and the plan says so instead of pretending the criterion was met. It does not measure data quality with new human annotators, nor improve the automatic classifier's performance — those are later stages, with costs of their own. And it does not guarantee the automatic checking will work on the first try: the test suite has never been executed on the kind of machine the checker uses, and the plan already carries the fallback in case it breaks.
