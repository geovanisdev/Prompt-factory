Contexto

A Camada 0 fez o repositório dizer a verdade sobre si mesmo. A Camada 1 o torna público — e histórico público não se apaga. Por isso ela tem uma única operação destrutiva, o git filter-repo, cercada de tudo o mais: espelho antes, verificação em clone limpo depois, e o flip de visibilidade como último ato, feito por você na interface do GitHub.

O que sai da história é backups/bancada.sql: um dump do banco da Bancada com texto derivado do corpus (inclusive um nome próprio vindo de um prompt do WildChat) e os gabaritos escondidos das sintéticas. Ele contradiz a política do próprio .gitignore, que mantém fora do git tudo o que carrega corpo de prompt. O recon corrigiu a premissa do PRD: o arquivo está em um commit (840d537, 2026-08-12), não em 68 — o PRD contou os commits do repositório. Esse commit também criou scripts/backup_bancada.py, então ele não fica vazio depois do filtro: sobrevive com outro SHA. Todo commit posterior contém o blob na árvore e será reescrito — inclusive os 4 SHAs que o handoff da Central cita e os 5 que o plano da Camada 0 cita. O c827c6df do CLAUDE.md, que o PRD mandava corrigir, não é commit deste repositório (é revisão do Hub): lá não há nada a mexer.

Os outros dois requisitos de sanitização são de conteúdo no HEAD. Caminhos pessoais aparecem em 11 linhas de 9 arquivos, e um deles é configuração: [pedidos] material_dir aponta para a pasta local do material didático, e o código a lê só do settings.toml — tirar o caminho de lá exige dar a você outro lugar para pô-lo. As editoras aparecem em prosa dos docs da Central, num comentário do .gitignore, e em código: a tabela que deriva o nome da coleção do nome do arquivo mapeia "Identidade Saraiva". E há um detalhe que o PRD não previu sobre si: os critérios R13 e R14 citam as strings proibidas literalmente, então o git grep do critério acha o próprio PRD, para sempre.

Regras invariantes

  • Nada é reescrito sem o espelho conferido. Feito: mirror + bundle + dados humanos em F:\backups. O rollback do RK2 é git clone F:\...\repo.mirror.git.
  • Reescrever UMA vez. Todo conteúdo (R13, R14, script de backup, .gitignore) entra em main ANTES do filtro; os SHAs citados são corrigidos DEPOIS, lendo o commit-map que o filter-repo grava. Dois filtros gerariam dois mapas e dobrariam o risco de citação morta.
  • O filtro roda num clone fresco, nunca no checkout com worktrees; depois cada worktree faz fetch + reset --hard — que só toca arquivos rastreados, então os annotate.sqlite e a destilacao/ da worktree de briefs ficam onde estão.
  • Toda ação no GitHub que muda visibilidade, nome ou existência de repositório é sua, na interface — gh não está instalado, e essas ações são externas e de difícil reversão. Eu preparo, verifico e digo exatamente o que clicar.
  • Push com força só depois de você escolher a estratégia (decisão PC1) e só com aprovação no checkpoint do S05.
  • PowerShell não redireciona dados, uv pelo caminho completo, não editar PRD/ADR além do que a decisão PC3 autorizar — as regras da Camada 0 continuam valendo.
  • Zero texto de corpus nos artefatos novos (docs/samples/): saem de uma Bancada com corpus vazio, como as capturas do R8.

Por que o S05 tem duas fases e o filtro vem no meio

O filter-repo reescreve todo commit a partir de 840d537. Conteúdo antes, filtro uma vez, SHAs depois pelo mapa: é a única ordem em que cada citação é corrigida exatamente uma vez — um segundo filtro geraria um segundo mapa e invalidaria as citações já corrigidas. E o clone fresco não é preciosismo: o filter-repo recusa rodar num repositório que não seja clone fresco, e com razão — as worktrees deste repositório guardam dados humanos não rastreados.

O que é isto, em 30 segundos

É o roteiro para abrir o projeto ao público sem levar junto o que não pode ir. Três tarefas: apagar da memória do projeto um arquivo que nunca deveria ter sido guardado nela, traduzir a porta de entrada para inglês, e só então virar a chave de "privado" para "público" — depois de conferir tudo numa cópia limpa, como um avaliador faria.

This is the roadmap for opening the project to the public without taking along what must not go. Three tasks: erase from the project's memory a file that should never have been kept there, translate the front door into English, and only then flip the switch from "private" to "public" — after checking everything on a clean copy, the way an evaluator would.

Por que isto existe

Um sistema de controle de versão guarda toda versão de todo arquivo, para sempre. Em 12 de agosto foi guardada uma cópia do banco de dados da plataforma de anotação — com texto derivado de conversas de terceiros, inclusive o nome de uma pessoa, e com as respostas escondidas de um teste de calibração. Apagar o arquivo hoje não basta: ele continuaria lá, em cada versão anterior. A única saída é reescrever a história do projeto sem ele, e isso muda o "número de série" de cada versão posterior — inclusive de dez versões que documentos do próprio projeto citam pelo número. Além disso, o projeto guarda em 11 lugares o caminho de pastas do computador do autor e, em vários documentos, o nome de três editoras cujo material foi processado localmente. Nada disso é crime; tudo isso é ruído que um repositório público não deveria carregar.

A version control system keeps every version of every file, forever. On 12 August a copy of the annotation platform's database was stored — with text derived from third-party conversations, including a person's name, and with the hidden answers of a calibration test. Deleting the file today is not enough: it would still be there, in every earlier version. The only way out is to rewrite the project's history without it, and that changes the "serial number" of every later version — including ten versions that the project's own documents cite by number. On top of that, the project stores in 11 places the folder paths of the author's own computer and, in several documents, the names of three publishers whose material was processed locally. None of this is a crime; all of it is noise a public repository should not carry.

O que muda daqui pra frente

Fica mais fácil mostrar o projeto: qualquer pessoa abre o endereço, lê em inglês e vê o selo de verificação — sem convite. Fica mais caro errar: depois de público, o que for publicado fica publicado, e é exatamente por isso que a ordem é rígida. O que não se desfaz é a reescrita da história, e ela é a única operação irreversível desta etapa — por isso há uma cópia completa de tudo guardada em outro disco antes de começar, e por isso a escolha de onde publicar a história limpa (o mesmo endereço ou um endereço recriado) é sua, com o trade-off explicado.

It gets easier to show the project: anyone opens the address, reads it in English and sees the verification badge — no invitation needed. It gets more expensive to be wrong: once public, whatever is published stays published, and that is exactly why the order is rigid. What cannot be undone is the rewriting of history, and it is the only irreversible operation in this stage — which is why a complete copy of everything is stored on another disk before starting, and why the choice of where to publish the clean history (the same address or a recreated one) is yours, with the trade-off spelled out.

O que isto NÃO diz

Não promete que o arquivo desaparece do servidor do GitHub no instante em que a história é reescrita: se a escolha for manter o mesmo repositório, cópias antigas podem continuar acessíveis por número de série até a limpeza do servidor, e o plano diz isso em vez de esconder. Não faz o vídeo de demonstração — ele precisa de você gravando. Não decide sozinho se os 25 commits assinados com o e-mail institucional devem ser reassinados: é decisão de identidade, e é sua. E não vira a chave: a mudança para público é feita por você, na interface, depois de eu mostrar o resultado da conferência.

It does not promise the file vanishes from GitHub's servers the instant history is rewritten: if the choice is to keep the same repository, old copies may remain reachable by serial number until the server's cleanup, and the plan says so instead of hiding it. It does not make the demo video — that needs you recording. It does not decide on its own whether the 25 commits signed with the institutional e-mail should be re-signed: that is an identity decision, and it is yours. And it does not flip the switch: the change to public is made by you, in the interface, after I show you the result of the check.
